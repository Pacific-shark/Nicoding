# 场景学习 · 2026-09-11

八个方向使用独立工作面，入口为 `#journey/:domain/:stage`。省略 stage 时恢复上次步骤。原 60 个知识页仍用于原理、代码题和查阅，知识页与场景双向链接。

| 方向 | 操作与反馈 | 保存的产出 |
| --- | --- | --- |
| Python | 输入校验、逐行金额追踪、嵌套列表复制 | 输入与结果契约、复制边界 |
| Web | 真正执行定时回调，改变请求顺序、过期保护与失败状态 | 联调时间线 |

## 数据与计算边界

- 浏览器训练为 16 → 8 → 1 的 MLP，解析梯度、全批次 SGD、固定种子 42。在 Worker 内运行，离开章节会终止尚未完成的计算；已完成的实验仍保留。
- 数据是教学合成数据，切分存在相似措辞，不能以这里的指标证明真实泛化或业务收益。测试集不参与梯度和模型选择。
- 卷积、递归状态、Attention 和遮词章节是数值机制实验或实验设计，不会自动训练和替换分类器的架构。
- `public/learning/comment-classifier.py` 是可独立下载的 PyTorch 对照源代码，内嵌同一数据，支持复现浏览器导出参数。当前环境未安装 PyTorch，已验证 Python 语法、无依赖数据模式与网页数据一致，未执行 PyTorch 训练。
- RL 实际训练表格 Q-learning；没有实现 DQN/PPO 训练。Web 使用本地定时回调；幂等回归使用确定的交错调度；客服规则是虚构文本，检索是关键词匹配，示范答复是受限模板，不调用在线模型或实际工单。
- `state.journeys` 保存场景数据和证据，与知识点掌握记录分开。新增场景包含在全局备份内；单独导出的场景档案是交接文件。导入时校验模型、轨迹、训练历史等结构，避免异常数据导致渲染失败。

## 固定学习布局与视觉验收

桌面采用全局导航 + 左侧步骤 + 固定课程标题 + 独立滚动正文。左栏可自行滚动。移动端用紧凑标题与章节下拉框，底部保留主导航。原引用/复制课程也改为固定标题与左栏。

与本轮生成的 1536×1024 深度学习概念图逐项比对：

1. 布局保留左侧八阶段、上方项目标题、正文左右需求/数据区域与下方输入工坊。
2. 保留标题及项目接单内容，删除虚构邮箱和无关旧日期；把 1000×768 示例改为实际 48×16 输入。
3. 使用已有 Noto Sans SC 字体并补齐新增字库。正文与控件略紧凑，以容纳可操作表单；最终增大正文和表格字号。
4. 保留暖白背景、浅边线和低饱和紫色重点，其他方向通过自己的工作面及轻量强调色区分。
5. 保留需求信件和数据表之间的分隔、章标题间距和下方工坊分区；窄屏折叠为单列。
6. 验收选择用原生下拉框，便于键盘与手机操作；数值和曲线由实际计算产生，不使用概念图中虚构的嵌入值。
7. 保留用户认可的 Nicoding 标识和 Nico。学习时 Nico 收起为可展开按钮。数学与 Q 表网格是代码绘制的教学图形。
