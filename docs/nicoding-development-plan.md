# Nicoding 后续发展计划

日期：2026-09-10
版本：0.2，知识板块优先。
状态：分批实施中；首批实际范围见 [交付记录](knowledge-first-release.md)。
现状基线：Git 提交 `5f97a82`，已上线任务、代码、结果并排的项目工作区。

## 1. 目标与优先级

近期目标：让已经借助 AI 做产品或开发、但基础不扎实的学习者，能理解关键机制、读懂实现、处理边界与错误，并在一个新任务中独立应用。

本版将知识板块提前。先重建课程的内容组织、表达方式和应用深度，完成不同类型的知识单元样板，再把这些单元接到项目训练中。原计划以优惠结算器项目作为第一项交付的安排，由本版替代。

保留 Nicoding 的暖色视觉、Nico、知识路线与现有项目工作区。课程中的表达方式按知识特点选择，导航、术语、操作和反馈保持一致。首页和品牌的全面视觉翻修留待课程样板明确后评估。

先以发起者自己的学习为主要使用场景，再考虑邀请少量背景相近的人自愿试用。没有假设已有开发团队、云服务预算或稳定用户规模。是否面向公众运营，后续再定。

## 2. 已核实的缺口

当前有 8 个方向、60 个知识节点，已有代码运行、部分代码挑战、选择题和解释练习。因此问题不能概括为“完全没有交互”。主要缺口是：正文、机制演示和真实应用之间缺少连接，不同知识仍套用相近的五步结构。

代码依据：`src/data/schema.js` 中正文主要存为标题与文字对；`src/components/LessonText.jsx` 只呈现段落、行内代码和代码块；`src/components/Lesson.jsx` 将概念、示例、练习等放在分开的步骤中。这样的结构适合短文与小例子，缺少计算图、过程回放、数据实验等内容的承载方式。

| 已检查的课程 | 现有内容的价值 | 距离应用还缺什么 |
| --- | --- | --- |

## 3. 课程的组织与表达

### 3.1 先建立内容地图

将现有 60 个节点视为主题入口，逐一标明：学完能做什么、必要先修、当前覆盖、待补内容、需要的实验、对应项目、来源与维护版本。一个主题可以包含多个学习单元，不预设每个节点都能在 30–60 分钟内讲完。

例如，“Attention 与 Transformer”应拆开注意力计算、掩码与位置、多个头、Transformer 模块及应用实验。“PPO 与 SAC”需要分别组织。拆分依据是理解和应用所需的台阶，不以新增节点数量作为成果。

主题入口让学习者能看见前后关系、目标深度和当前进度；进入课程后，优先呈现当前要解决的问题。先修提示说明具体会用到什么，可以跳转补学并返回原位置。兴趣探索允许直接进入，不能仅因未点亮前置节点就锁住所有内容。

### 3.2 根据知识特点选择表达方式

| 知识类型 | 主要表达与操作 | 学习者需要完成的事情 |
| --- | --- | --- |
| Python / JS 的值、引用、作用域 | 代码逐步执行；变量与对象关系图；作用域视图；前后状态对照 | 先预测，再执行验证；定位共享、覆盖或作用域错误并修复 |
| 异步、请求与状态 | 时间线、队列、请求与响应顺序；可调整的延迟和失败情境 | 复现竞态、解释执行顺序，加入取消或过期响应保护并验证 |
| 工程、接口与调试 | 数据流、接口契约、日志与 diff 对照、逐步暴露的故障案例 | 缩小问题范围，提出可复现例子，选择修改边界并检查回归 |
| 数学与概率 | 图像、向量、矩阵和公式联动；可展开的推导；小数值例子 | 将图中的变化对应到符号，说明假设，手算一小步并用代码核对 |
| 机器学习 | 样本表、分布、分类边界、指标与曲线联动；条件可控的对照实验 | 检查数据与切分，比较基线，选择指标和阈值，解释错误与限制 |
| 深度学习 | 张量形状、计算图、梯度与训练曲线；对应的真实框架代码 | 跟踪一次计算，诊断维度或梯度问题，完成可复现的训练与验证 |
| 强化学习 | 可操作的环境、轨迹、奖励、价值与策略视图；多次运行结果 | 解释一次更新，比较探索和策略选择，在新条件下检查稳定性 |
| 大模型、RAG 与 Agent | token / 上下文视图、分块与检索实验、证据对照、工具调用轨迹 | 定位失败环节，修改一个条件，检查质量、边界、延迟和实际成本 |

这是表达方式的选择表，不是每个领域只准使用一种模板。一个知识单元可以组合短讲解、静态图、交互实验、代码和练习。

文字仍承担定义、推理、条件和限制说明。关系稳定时用静态图；过程难跟踪时用可暂停和逐步播放的演示；参数影响结果时用真正计算的交互实验。视频主要用于环境搭建和工具操作等确有必要的部分，提供字幕和跳转，不用自动播放或整页视频替代所有课程。

### 3.3 页面体验

- 用课程自己的章节名称取代所有内容共用的五个步骤。用户能看见当前位置、前后关系、已完成产出和下一项任务。
- 桌面端让当前解释与相关实验靠近；需要时并排，点击公式中的量能定位到图或代码。代码、图和结果描述同一份数据与同一次操作。
- 实验先给一个明确问题，例如“第二次请求为什么多出上一位用户的记录”；允许预测、单步、回退、重置和比较两种情况。
- 第一次进入只展开当前所需的信息，推导、API 细节、补充反例按需展开；主线必须完整，不能把关键解释全部藏在折叠区。
- 手机端按学习顺序排列，保留当前实验状态，减少横向拖动；复杂矩阵可切换局部视图，并提供文本或表格等价呈现。
- Nico 可解释当前步骤、提示遗漏的观察和协助返回卡点；不遮住公式、编辑器、运行结果或系统对话框。最高图层并不适合所有场景，拖动、收起和焦点行为需要一起设计。

## 4. “应用级”的内容标准

本计划中的应用级，是能在给定范围内完成真实任务、说明选择、处理典型失败，并在相似新问题中迁移；不意味着每一节都覆盖完整生产系统，也不意味着完成网站就获得就业能力认证。

一个面向应用的完整单元需要覆盖以下目标，具体组织和篇幅由内容决定：

1. **认识问题。** 为什么需要这个概念，原来的做法在哪里失败；用一个足够小的例子建立直觉。
2. **理解机制。** 必要的定义、执行规则、公式、假设与维度；关键步骤能逐步解释，不能只靠类比。
3. **实现与观察。** 把图或推导对应到实际代码和 API，能修改输入、观察中间结果并核对。
4. **处理实际约束。** 包含边界、错误、数据问题或工程取舍；解释什么情况下不适用。深入程度与该单元的目标相称。
5. **独立迁移。** 给出未直接演示过的变式，提交代码、分析或设计，并按明确标准检查。记录所用帮助。

课程素材要包含解释、例子、反例、逐级提示、参考结果、可执行练习及来源。费曼式解释用于暴露理解缺口：要求解释具体过程、举例和反例，并结合运行结果或标准反馈修正。不能用“写够十个字”或复述术语判断学会。

对内容篇幅不设统一字数。一个具体语法点可以很短；梯度、Attention 或策略优化可拆成连续多个单元。推导和完整应用之间要有可走通的路径，不能用一句“自行阅读官方文档”替代课程后半段。

## 5. 第一批三个知识单元样板

先选择三种差异明显的内容来验证课程设计。它们是产品样板，**不是要求初学者按此顺序跨级学习**；每个样板都必须指出或补齐必要先修。

### A. Python 引用、复制与共享状态

目标：解释赋值、原地修改和复制的差异，修复跨调用与嵌套数据的意外共享。

学习过程：变量与对象关系 → 逐步执行赋值与修改 → 对比浅复制和深复制 → 默认参数跨调用共享 → 对照两种修复及其契约 → 处理一个新的嵌套配置或订单场景。

表达：左侧代码与当前行，右侧对象关系及状态变化。先预测哪个对象会变，再揭示结果。展示的是对象身份与关系，不伪装成真实内存地址。预设案例的演示标明支持范围；能编辑的范围与实际执行结果保持一致。

深度：不仅学会将默认 `[]` 改为 `None`，还要理解调用者显式传入列表时是否应保留共享，为什么浅复制不能隔离所有嵌套修改，以及深复制也不是所有场景的默认选择。

产出：一次预测、一次错误复现、一份修复、一条能抓到原错误的检查，以及对新场景中共享边界的解释。应用入口可接到现有优惠结算器的数据处理任务。

### B. 从混淆矩阵到阈值选择

目标：能根据标签、预测分数、数据切分和明确代价，提出阈值方案并说明限制。

学习过程：逐条样本对照真实标签与预测 → 从样本生成四格表 → 理解指标分母 → 调整阈值并观察分类变化 → 比较不同代价与触达预算 → 在验证数据上选择方案 → 在保留测试数据上报告结果 → 分析错误样本与分组差异。

表达：一份明确标为教学用途的数据，联动样本表、阈值滑块、混淆矩阵、PR 曲线和代价表。点选一个错误格子能定位到对应样本；公式中的计数来自同一数据。观察结果再写选择理由，随后用 scikit-learn 核对关键数值。

深度：分清分数与概率、指标与业务价值、模型区分能力与决策阈值；解释类别分布和数据漂移怎样影响使用判断。校准等延伸内容给出先修与后续单元，不一屏塞完。营销例子中的误判代价是显式假设，预测购买不等于证明营销带来了增量购买。

产出：可运行的指标计算、阈值与假设说明、保留数据上的报告、失败案例及一个新代价条件下的调整。应用入口为现有指标评估器，逐步补成完整评估实验。

### C. 从计算图到真实训练循环

目标：解释梯度如何得到、参数何时更新；运行并调试一个小模型的训练与验证。

学习过程：线性预测与损失 → 标量计算图的前向值 → 局部导数与链式法则 → 数值差分核对 → 真实 PyTorch autograd 对照 → 批次与张量形状 → 训练、验证和保存 → 人为植入错误后的定位与修复。

表达：代码、计算图和当前张量/梯度对应；可以停在某一步预测下一个值。学习率实验与训练曲线使用实际计算。默认先看一条简单路径，符号推导和多路径梯度累加逐步展开。

深度：区分 backward 与 optimizer.step、训练模式与梯度记录；处理意外广播、梯度未清零或被切断等典型错误；在独立数据上解释结果。单步图解与完整训练分别标明目标，不能将一个标量更新例子称作完整深度学习训练。

产出：一段机制解释、一个梯度核对、一个可复现的小模型实验，以及对新故障的修复证据。浏览器承载小型实验；真实 PyTorch 部分交付配套 Notebook 或工程，含环境版本、数据说明、运行步骤、检查和参考结果，而非只给一个外链。

## 6. 后续知识覆盖与深度路线

| 路径 | 需要形成的连续主线 | 对应应用成果 |
| --- | --- | --- |
| Python | 值与类型、控制流、函数与作用域、容器与引用、异常、迭代器/生成器、模块与环境、文件与数据处理；按需引入类与上下文管理 | 能读懂并维护一个有输入输出、异常和测试的小工具 |
| JavaScript / Web | 类型与转换、作用域与闭包、对象更新、模块、异步与事件循环、DOM/事件、HTTP、运行时校验；随后学习 TypeScript 与组件状态 | 带保存、加载、错误和并发状态的可用页面 |
| 工程 | 需求与接口契约、Git/diff、测试与调试、SQL/数据关系、事务与幂等、模块边界、日志、配置与部署；算法与数据结构按实际问题补齐 | 接受一次变更，说明修改范围，并用运行和回归结果交付 |
| 数学 | 向量与矩阵、函数与导数、链式法则、概率与条件概率、统计估计、信息量与优化 | 能把公式中的量对应到数据、形状和代码，说明主要假设 |
| 机器学习 | 任务与数据、切分/泄漏/预处理、基线与指标、线性与树模型、模型选择、聚类与降维、推荐与排序 | 可复现实验、错误分析、合理的算法选择与限制报告 |
| 深度学习 | 张量、自动微分、优化与泛化；再进入 CNN、序列、Attention/Transformer、自监督与生成模型各分支 | 小模型训练与诊断；后续完成选定架构的应用复现 |
| 强化学习 | Bandit、MDP、价值与 Bellman 关系、Monte Carlo / TD / Q-learning、函数近似与 DQN、策略梯度/Actor–Critic，再分别进入 PPO、SAC | 在明确环境中对照基线，分析奖励设计、探索、多个随机种子与失效条件 |
| 大模型与 AI 应用 | token/上下文、结构化输出与工具契约、RAG 与评估、Agent 的状态/权限/停止条件；随后进入 SFT/LoRA/量化及其适用边界 | 有证据、可评估、能处理失败和停止的应用；记录完整任务成本 |

此表是覆盖检查的框架，具体拆课与缺口表属于下一项交付。需要兼顾基础与进阶，但按先修和应用任务组织，避免同时铺开所有算法。已有高级内容继续可访问，深度标签应明确区分概念认识、小实验、完整应用和研究延伸。

## 7. 分阶段交付与验收

按交付与验收推进。详细样稿和交互复杂度确认后再估算工期，不给尚无依据的完成日期。

| 阶段 | 交付范围 | 必须交付 | 验收重点 |
| --- | --- | --- | --- |
| M1 内容地图与样稿 | 现有知识板块审查；上述三个完整单元 | 60 个主题的覆盖与缺口表；推荐先修；三个逐段课程稿、交互分镜、练习、提示、参考结果和来源 | 题目与目标对应；关键机制有解释；从先修到应用没有靠一句外链跨过的断层；可明确判断哪里需要哪种媒体 |
| M2 可学习的课程样板 | 三个单元逐个实现，先完成 A 并修订，再完成 B/C | 可操作的机制图、数据实验、计算图；真实运行连接；按单元组织的反馈与进度；必要的 Notebook 配套 | 图、代码和结果一致；预测与操作有反馈；刷新可恢复；移动端、键盘、减少动效和文本替代可用 |
| M3 试学与应用连接 | 自己试学后再考虑 3–5 位自愿试用者；接回相应小项目 | 卡点与误解记录；独立变式；对照标准；一轮内容修订；知识与项目之间的双向入口 | 不依赖开发者现场补足题意；用户能解释机制、修复错误并完成新任务；不能只统计点击或完成动画 |
| M4 分批扩展 | 根据工作需求与样板结果选择下一组课程 | 连续的 Python/工程主线；随后扩展 Web/AI 或数据算法主线；复用素材与内容规范 | 新课达到相应目标深度，关键例子和练习经核对；维护负担可控 |

下一项具体工作是 **M1：完整知识地图与三个知识单元的详细设计**。优惠结算器保留为 A 单元之后的应用训练，再逐步加入读代码、复现错误、补边界、拆职责、接受变更、审查 AI diff 和独立变式。项目工作区继续服务这些任务，但不占用首轮课程重构的优先级。

账号同步可在跨设备保存成为实际障碍时并行推进；AI 助教在已建立课程标准与反馈案例后接入。二者不作为课程样板的前置依赖。

## 8. 内容、运行与学习记录的实现原则

### 内容与实验

将正文从单一段落列表扩展为有明确类型的内容块，例如解释、公式、关系图、执行轨迹、数据实验、代码、预测、故障练习和来源。不同单元组合使用，避免另一种形式的“大一统五步模板”。先从三个样板提炼组件，不预先建设通用课程编辑平台。

交互中的图、数值、代码与检查尽量共享计算依据。若只能做预设过程演示，应标明支持的案例和限制，不能让任意编辑后的代码继续播放不相关的动画。历史运行或录制结果与本次真实运行分开标示；未接模型时不模拟成已发出真实模型请求。

继续将浏览器运行限定在适合的小任务。较重训练或多文件服务用配套本地工程/Notebook 承接；明确环境、依赖、数据、运行顺序和结果检查。不能把完整模型训练强塞进现有短时运行器。

### 反馈与进度

- 预测、解释、代码和实验选择对应不同的验收方式。解释可对照具体要点和反例，试用中复核关键答案；不以字数或泛化的 AI 分数判断理解。
- 代码失败先显示实际输入、预期、结果或异常；结果绑定代码和检查版本，编辑后标明旧结果已过期。
- 逐级帮助包括提示观察点、局部例子和参考答案，保留使用程度。独立练习使用新例子，学习者可继续求助并另选变式再试。
- 记录接触过、借助帮助完成过、独立完成过，以及之后的复查。一个主题的点亮可展示不同层次，不把一次通过当成永久掌握。
- 旧版 `nicoding.learning.v1` 记录保留为旧版完成证据；先备份再迁移，不清空既有代码、笔记，也不直接升级成新标准下的能力证明。
- 保存关键提交与检查快照，不无限记录按键；课程定义与个人记录分开。课程、活动和证据使用稳定 ID 与版本。

### 权威资料与内容质量

优先核对官方语言文档、框架教程、开放教材和原始论文；采用原创中文讲解、自己的例子和练习，标注到具体章节。检查再利用授权，不把整本教材抓取改写后当作自有课程。链接和生成文字本身都不能代替事实核对与运行验证。

为课程记录资料版本、验证环境、审阅状态和最后检查日期。公式、维度、例子、参考实现和练习契约分别核对；自动检查负责结构和可执行结果，教学清晰度通过试学补充。开源资源可以支撑知识的正确性，不能自动保证本产品教得清楚。

## 9. 后续服务与产品决策

账号的最小范围是登录、访客数据迁移、备份、恢复、导出和冲突处理。双设备并发编辑应保留冲突版本，不能只按时间静默覆盖。选服务商前估算用户规模、记录体积和费用，不预设永久免费。

AI 优先用于解释反馈、针对错误追问、审查改动。输入以当前任务、必要代码与最新结果为主；用核对过的案例评估误导和泄题。模型不可用时课程与基本检查仍可使用。节省 token 要看完成质量、实际总用量、重试和耗时，没有接入模型时不展示虚构的精确节省率。

首批观察独立变式、解释成立程度、调试证据、所用帮助、卡点及约一周后的新题表现。邀请与收集记录前说明用途并获得同意；小规模试用用于发现问题，不宣称普遍学习提升或因果效果。站点无法可靠识别外部 AI 帮助，不能包装成严格监考。

暂缓大规模机械生成课程、社交排行、支付、通用聊天首页、完整云端 IDE，以及无学习用途的动效。研究级推导可以作为后续分支，但应用主线不能跳过先修、实现、评价和失败分析。

## 10. 当前已核对的设计参考

- [Python：copy — 浅层与深层复制](https://docs.python.org/3/library/copy.html)：核对赋值、引用、浅复制与深复制的语义；课程实现另标实际运行版本。
- [scikit-learn：模型评价](https://scikit-learn.org/stable/modules/model_evaluation.html)：核对精确率、召回率以及由标签、分数和变化阈值构成的 PR 曲线；课程补充自己的业务假设与任务。
- [PyTorch：Automatic Differentiation with torch.autograd](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)：计算图、可运行代码与自动求导相互对应的官方入门实例，作为 C 单元的核对依据之一。
- [IES：Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/practiceguide/1)：支持将图与语言解释结合、例题与独立解题交替、主动回忆和间隔学习等设计原则。
- [CMU：Concrete Strategies for Active Learning](https://www.cmu.edu/teaching/online/designteach/strategies/activelearning.html)：参考例题解释、错误步骤识别、标准对照与陌生情境应用等活动。

上述来源分别用于核对内容和设计原则，不构成对 Nicoding 学习效果的验证。具体单元、交互、优先级和验收方式属于本项目提案。
